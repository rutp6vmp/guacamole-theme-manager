與 SSH 協定完成登入，傳送鍵盤指令，並在該容器檢查指令建立的檔案。

已通過：
1. 無探針時，實際 SSH 可用、管理員可加入活動 session、共享憑證可真的連入。
2. 新探針載入後，原生 connection ID 不能直接繞過一次性啟動資格。
3. 同帳號的另一個獨立登入、其他身份，都不能使用原登入的啟動資格；合法登入仍可用。
4. 已消耗及過期資格被拒絕；兩個併發 transport 嘗試只有一個成功並建立一份 lease。
5. API 拒絕來自 body 的身份欄位與非整數時長，資產由原生 READ 再次核對。
6. 原登入重新認證後仍可使用它自己尚未消耗的資格，不轉交給別的登入。
7. 用真正的 active ID 嘗試加入被拒絕；對真實活動 session 產生新共享憑證被拒絕。
8. 同帳號另一個登入不能關閉這個登入的 lease；非管理員不能經原生 API 刪別人的 session。
9. 顯式 terminate、原生管理員 DELETE、session-context revoke 與本地 deadline 都實際斷線。
10. 重複 terminate 冪等；關閉一人的 tunnel 時，另一人的 SSH 保持可用，且再次執行新指令確認。
11. revoke 後該登入不能建立新資格，先前尚未消耗的資格也不能再啟動。
12. 關閉閘道後，該目標內的 nohup 背景程序仍活著；沒有把閘道斷線當成 OS 任務終止。
13. SSH 目標沒有映射到主機 port；安裝探針只重建測試 Web，其他容器識別維持不變。

二、原創接入設計與可信登入綁定

以獨立 namespace pam-session-probe 實作，不改原來全拒絕型 pam-gate-probe。
每次 decorate 新建獨立 State；State 所屬的 UserContext 由 Guacamole 的認證 session
路由取得。Resource 直接閉包持有該 State，不接受請求 body 或 header 指定 owner。
即使兩次登入的 username 相同，State 仍不同；不以 username 當作登入 session key。
redecorate 只在伺服器提供的 previous context 類型與 provider/subject 一致時保留 State。

這證明「以伺服器認證 context 綁定資格」在此 1.6.0/JDBC 路徑可行，並沒有取得、
儲存或印出 Guacamole bearer token 或公開 session ID，也不宣稱是跨 provider 穩定身份。
偷走整個 bearer token 等同進入原登入，這個 POC 不是裝置綁定或 token 失竊防護。

啟動資格使用 UUID 隨機識別碼，以 pam-intent-* 的暫時 connection identifier 回傳。
State 內保存固定原生 connection reference、monotonic 到期時間、最長 lease 時長與消耗旗標。
真正 connect 前在同一 State 原子消耗，並再次查原生 Connection；原生 ID 的 connect 直接拒絕。
資格即使遇到連線失敗也不恢復可用，需重新申請；不把失敗重試當成重放同一資格。
group 與 active join 先採拒絕，不透過核准一個 group 擴大為任意未來資產。

當前驗證界線：只以原生使用權作底層條件，尚未有合約、grant、MFA freshness、
policy_version、錄影義務或原子 session 容量扣除。原生權限快取的即時失效也未完成。
本 probe 的最多 16 個暫存 intent 是測試資源上限，不能冒充正式併發 session 配額。

三、工作階段與失敗語義

connect 回傳真正 tunnel 後建立 Lease，再回傳 DelegatingGuacamoleTunnel 包裝。
Lease 記錄 startedAt/deadlineAt、ACTIVE/TERMINATING/ENDED/FAILED、reason、
terminationRequestedAt 與 terminationConfirmedAt。只有 close 完成且 tunnel 不再 open
才寫確認時間；browser 實際斷線另由獨立的 Guacamole.Client 觀測。
截止時間採 System.nanoTime 計算，UTC Instant 僅作記錄；單節點 ScheduledExecutor 執行 close。
顯式 terminate、deadline、client close 及 provider shutdown 都只處理自己追蹤的 tunnel。
native Directory.remove 另用原生管理員 API 驗證；沒有假設 getTunnel 對一般使用者可用。

context revoke 只撤這一次登入，不能被描述為整個人、廠商、合約或所有節點的撤權。
新的合法登入可以有新的 State，未來跨登入撤權必須回到權威政策／grant 資料。
已在進行的 connect 不能透過這個介面即時取消底層握手；返回後會重查 revoke 並關閉。
期限從 native connect 返回後起算，不能宣稱已控制握手前的全部時長。

狀態與 lease 在記憶體，prototype 保留到 provider shutdown，沒有耐久恢復、正式清理／
重試 jobs、控制平面失聯演練、owner lease/fencing 或 HA。Web 重啟後意圖不能沿用。
這些限制仍在 G02-02、F07/F08 及 P03/P07 ledger 保留為未完成範圍。

四、隔離 API（僅此 probe，不是 /pam/v1 產品 API）

基底：/api/session/ext/postgresql/pam-session-probe
POST /intents                     固定三欄：connectionId、ttlMillis、leaseMillis。
GET  /leases                      只列該登入的 lease 摘要，不回傳密碼或 tunnel。
POST /leases/{id}/terminate        只允許同一登入管理自己的 probe lease。
POST /revoke                      撤銷本次登入的資格與 lease。

這些端點使用現有 Guacamole session 驗證；測試請求透過 Guacamole-Token header。
未驗完整正式 CSRF/CORS/IdP 政策；不得在正式 profile 對外提供。
probe 額外要求 PAM_SESSION_PROBE_ENABLED=fixture-only、JDBC 與 gtm-* 合成身份；
沒有這項明確測試設定就不發資格。這是測試隔離條件，不是正式使用者授權策略。
