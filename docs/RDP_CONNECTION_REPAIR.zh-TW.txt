RDP 連線內部錯誤排查與修正紀錄
處理日期：2026-11-01（Asia/Taipei）
範圍：使用者指定的一筆既有 RDP 連線；Guacamole 1.6.0。
本文件以角色／欄位稱呼端點，不收錄實際內網位址、帳號、密碼、token 或原始日誌。

一、直接原因與證據
1. Web、guacd、PostgreSQL 均正常執行；Web 近期有 Connection refused。
2. 指定連線實際儲存的 proxy_port 為 0，而非 NULL。
   JDBC 會使用非 NULL 的連線層級覆寫值，因此不會沿用系統 guacd 連接埠。
3. 修正為 NULL 後，Web 容器到既有 guacd:4822 的 TCP 檢查通過。
   使用者後續重試已進入 guacd，錯誤變為目標 RDP 連線失敗。

二、第二段網路問題
使用者的 Windows 遠端桌面客戶端可透過原外部網址連線，
但 Guacamole 主機與 guacd 容器連原外部 RDP 連接埠皆逾時。
這證明不同來源的可達性不同；尚未判定是 NAT loopback、路由或防火牆規則。
使用者提供目標 Windows 的內網 IPv4 後，定向檢查結果：
  主機 → 目標內網 IPv4:3389：通過。
  guacd → 目標內網 IPv4:3389：通過。
  主機／guacd → 目標內網 IPv4:原外部連接埠：不通。
RDP X.224 協商成功，伺服器選擇 NLA；探測未傳送帳密或開啟 Windows 桌面。

三、實際修正
只處理指定連線，事前將非機密設定保存於 root 專用目錄：
  /var/lib/guac-theme/connection-repairs/
  proxy_port：0 → NULL（沿用系統 guacd 設定）。
  hostname：原外部網域 → 使用者確認的目標 Windows 內網 IPv4。
  port：原外部轉送埠 → 實測可通的內部 RDP 埠 3389。
  security：rdp → any（介面「任意」，自動協商；目標已回應支援 NLA）。
更新採限定連線與預期舊值的交易；前置條件不符時回滾。
內網設定交易首次執行失敗並回滾，修正後重試成功，已重新讀取核對實際值。
未改 Windows／Guacamole 登入帳密、連線數限制、權限或其他連線。
未重建或重啟任何正式容器；新連線會讀取新設定。

四、憑證處理
標準 TLS 驗證回報 self-signed certificate（驗證碼 18）。
已向使用者說明信任行為，並取得「確認信任，啟用首次信任並記住憑證」的明確回覆。
只為這筆連線設定 cert-tofu=true；ignore-cert 未啟用。
啟用 TOFU 不代表本輪已完成首次記錄，需在實際成功連線時由 FreeRDP 建立記錄。
現有 guacd 未掛載獨立憑證持久化 Volume；重建容器可能遺失首次信任記錄，
若需跨重建固定信任，另規劃持久化與備份，或部署可驗證憑證／經獨立核對的指紋。

五、驗證界線與使用者操作
已通過：儲存設定核對、Web→guacd TCP、guacd→內網 RDP TCP、RDP NLA 協商。
尚待：使用者從原 Guacamole 畫面按「重新連線」，確認帳密驗證與桌面顯示。
未以內網可達或協商成功冒充完整 RDP 桌面驗收，也不代表 PAM 錄影／審批已完成。
若編輯頁在修正前已開啟，先重新整理再編輯，避免將舊設定重新存回。

六、同日再次回報仍失敗的追查
使用者回報相同錯誤後，再次核對發現：儲存設定已回到原外網端點、
proxy_port=0、security=rdp，且 cert-tofu 不在目前參數中。
尚未確認是舊編輯頁、其他操作或其他來源重新寫入，不能直接歸因於使用者。
已保存當次非機密快照，採舊值條件交易再次恢復已確認的內網／代理／TOFU 設定。
保留帳密、權限與其他連線，不重啟服務。

另在先前確實使用 Negotiate (ANY) 的 RDP 重試中，guacd 記錄：
  Authentication failure (invalid credentials?)
代表該次已到 Windows 登入驗證階段，仍不能據此判斷究竟是密碼、
帳號／網域格式、帳號狀態或 Windows 登入政策；尚未確認桌面成功。
僅以布林值核對格式：帳密非空、非遮罩佔位符、非動態密碼 token、無首尾空白。
未輸出或更改密碼，未自動重試 Windows 帳密。
再次核對 guacd 首次信任儲存檔已含目標主機條目；僅輸出匹配布林值，未輸出條目內容。
已請使用者在能成功登入的 Windows 遠端桌面執行 whoami，確認實際身分後再處理。

七、使用者提供 whoami 後的本機帳號設定
使用者提供的成功工作階段身分為「目標 Windows 電腦名稱\\administrator」，
確認應以該電腦的本機帳號範圍驗證；實際電腦名稱只保存在私有修正紀錄，不隨套件公開。
核對既有連線仍使用已確認的內網 3389、系統 guacd、any 與核准的 cert-tofu。
既有 username 為 administrator，domain 尚未設定。
已保存非機密快照，以連線、端點、使用者名稱及預期舊值為條件，
只將 domain 設為使用者確認的 Windows 電腦名稱。
讀回核對 domain 正確，其他非機密參數與先前一致；未讀取或修改密碼，未重啟服務。
此為依已確認身分消除帳號範圍歧義，不能單憑修改成功認定驗證失敗原因已排除。
已請使用者重新整理並重連；Windows 帳密驗證與桌面仍待實際成功確認。

八、使用者確認成功（2026-11-01／Asia/Taipei）
使用者在補上本機帳號範圍後明確回覆「可以了」。
本次指定連線的使用者端連線驗收據此記為成功；代理未直接查看 Windows 桌面，
也未另行驗證聲音、剪貼簿、檔案傳輸、重新開機後連線或其他目標。
已確認的直接錯誤為 guacd 連接埠 0，以及 Guacamole 來源無法連原外部 RDP 端點。
其他調整包含自動協商、使用者核准的首次信任及明確指定本機帳號範圍。
這些調整先後進行，沒有逐一還原對照，因此不能將每個調整都宣稱為獨立必要條件，
也不能據此斷定原密碼錯誤或網域留白在所有本機帳號情境都不可用。
本紀錄不代表完整 PAM、安全錄影或全部協定矩陣驗收通過。
